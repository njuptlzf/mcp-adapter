# Requirements

## Context

v3.1 milestone is derived from `docs/upstream-merge-retrospective.md` (938 lines), the multi-perspective reflection on the first real `git merge upstream/main` attempt (2026-07-01) that produced 11 conflict files and ~768 lines of Pi-coupling re-introduction.

3 categories of requirements:
- **MERGE** (4 reqs): Update SKILL.md policy + protocols so conflicts resolve at the policy/protocol level, not case-by-case.
- **ARCH** (5 reqs): Decompose large files so future conflicts resolve at the file/section level, not function/line level.
- **CI** (3 reqs): Add defensive guardrails so future conflicts surface earlier and architecture drift is auto-detected.

12 total requirements, all satisfied (12/12).

## Requirement Definitions

### MERGE-01: Default `--theirs` policy in `assess` rows

- Update SKILL.md §4.1 row for `assess` to read "Default `--theirs`" (prefers upstream improvements) instead of "0 hits → `--theirs`; ≥1 hit → §4.2b follow-up flow"
- The §4.1 Pi-coupling marker grep becomes **advisory** — 0 hits = clean accept; ≥1 hit = log warning + accept upstream + optional follow-up issue
- For same-function conflicts, follow §4.4 5-step protocol
- Priority: Must

**Implementation**: `skills/upstream-merge/SKILL.md` §4.1 (commit ebb7ed8)

### MERGE-02: §4.2b soft follow-up (5-step → 2-step)

- SKILL.md §4.2b reduces from 5-step mandatory follow-up to 2-step soft follow-up
- Step 1 (mandatory): `git checkout --theirs <path> && git add <path>`
- Step 2 (best-effort, only if `gh` CLI authenticated): optionally open follow-up issue
- "Removed from v1" rationale blockquote explaining why steps 2-5 from the original 5-step flow were removed
- Priority: Must

**Implementation**: `skills/upstream-merge/SKILL.md` §4.2b (commit ebb7ed8)

### MERGE-03: Conflict hunk independence check (4 categories)

- New SKILL.md §3.5 "Conflict hunk independence check"
- awk-based function-extraction script that prints each conflict hunk's containing function
- 4-category decision matrix: different function / same function different section / same function same section / import region
- Each category has 解决策略 + 自动化程度
- Priority: Must

**Implementation**: `skills/upstream-merge/SKILL.md` §3.5 (commit d48bf3c)

### MERGE-04: Same-function 5-step protocol

- New SKILL.md §4.4 "Same-function conflict resolution protocol"
- 5 mandatory steps:
  1. Extract ours: `git show :2:<file> | sed -n '<start>,<end>p'`
  2. Extract theirs: `git show :3:<file> | sed -n '<start>,<end>p'`
  3. View function context: full function body for both versions
  4. Classify merge mode (append / replace / wrap)
  5. Document decision in commit body with mode + decision + rationale
- Empirical reference: commands.ts 3 hunks (append mode) + index.ts mcpAdapter 343-line hunk (replace mode)
- Priority: Must

**Implementation**: `skills/upstream-merge/SKILL.md` §4.4 (commit d5341af)

### CI-01: GitHub Actions Pi-coupling guard

- New `.github/workflows/check-pi-coupling.yml` runs on every PR to main/v1.0

- Priority: Must

### CI-02: `upstream-divergence.ts` `--json` mode

- `scripts/upstream-divergence.ts` extended with `--json` output mode

- Fields: upstream_ref, diverged_count, registered, diverged_but_not_registered, stale, default_resolved_by_category, exit_code, hunk_independence_note, schema_version, schema_documented_in
- hunk_independence NOT predicted in pre-merge (requires conflict markers); emits note pointing to SKILL.md §3.5 awk script for in-flight analysis
- Priority: Must

**Implementation**: `scripts/upstream-divergence.ts` +24 lines (commit a21aa1b) + retrospective §13 documentation (75 lines)

### CI-03: Fork-only ratio guard

- New `.github/workflows/check-fork-only-ratio.yml` runs on every PR to main/v1.0
- Counts new files vs modified files in PR (vs `origin/main`)
- Computes modify-to-new ratio
- Target: ≤ 2.0 (WARN at >2.0, FAIL at >5.0)
- Soft check: extreme ratio (no new files but many modifications) triggers `::error::` + exit 1
- Implements SKILL.md §6.3 future-proofing rules as guidance
- Priority: Must

**Implementation**: `.github/workflows/check-fork-only-ratio.yml` (101 lines, commit 73dd8a1)

## Out of Scope (Explicit Exclusions)

- **Not changing upstream content** — fork is downstream, not adversarial
- **Not introducing new npm dependencies** — avoid scope creep
- **Not breaking Phase 1-12 work** — backward compatibility required
- **Not refactoring interfaces/** — abstractions are complete and tested; the debt is in core file-level architecture
- **Not removing the universal-mcp architecture** — Phase 12 deliverables (bin/mcp-server.ts, InlineMcpAdapter, etc.) are stable
