<objective>
Replace the hardcoded `getPiGlobalConfigPath` with an agent-aware path abstraction so the universal adapter can be reused by non-Pi agents (Claude, Cursor, etc.). Pi behavior must stay byte-identical.

Purpose: Phase 1 moved Pi packages to optional peer dependencies, but `config.ts` still bakes in `getAgentPath("mcp.json")` from `agent-dir.ts`. Without an abstraction, calling `loadMcpConfig()` from another agent would still read `~/.pi/agent/mcp.json`. This plan introduces a small `AgentPathResolver` interface and threads it through `config.ts`.
Output: `interfaces/agent-paths.ts` (resolver contract + Pi default), updated `config.ts` (uses resolver), and a test file proving non-Pi agents can resolve their own paths.

Scope guardrails (from prior decisions):
- Project-level paths (`.mcp.json`, `.pi/mcp.json`) are agent-agnostic and unchanged.
- `agent-dir.ts` stays as the source of truth for the Pi-specific path; it is wrapped, not deleted.
- Backward-compat default: any caller that does not supply a resolver still gets the Pi path.
- Do not touch sampling/elicitation handlers, `index.ts` default export, or MAPPING.md in this plan.
</objective>

    ```ts
    import { getAgentPath } from "../agent-dir.ts";

    export type AgentId = "pi" | "claude" | "cursor" | string;

    export interface AgentPathResolver {
      readonly agentId: AgentId;
      /** Absolute path to the agent's global MCP config file (e.g. ~/.pi/agent/mcp.json). */
      globalConfigPath(): string;
      /** Optional per-agent project override filename. Default: ".{agentId}/mcp.json". */
      projectConfigName?(): string;
    }

    export function createPiResolver(): AgentPathResolver {
      return {
        agentId: "pi",
        globalConfigPath: () => getAgentPath("mcp.json"),
        projectConfigName: () => ".pi/mcp.json",
      };
    }

    export const DEFAULT_AGENT_RESOLVER: AgentPathResolver = createPiResolver();

    /**
     * Resolve the global MCP config path for a given agent.
     * `overridePath` (if provided) wins — same semantics as the previous getPiGlobalConfigPath.
     */
    export function resolveAgentGlobalConfigPath(
      resolver: AgentPathResolver = DEFAULT_AGENT_RESOLVER,
      overridePath?: string,
    ): string {
      if (overridePath) {
        // preserve resolve() semantics from the prior implementation
        const { resolve } = require("node:path") as typeof import("node:path");
        return resolve(overridePath);
      }
      return resolver.globalConfigPath();
    }
    ```

    Use a top-of-file `import { resolve } from "node:path"` (not `require`) — Bun/ESM-safe. The `require` above is illustrative; replace with the static import.
