<objective>
Decouple the sampling subsystem from Pi-specific AI and UI types by introducing a generic `SamplingProvider` interface and a Pi-specific implementation. Core sampling logic becomes protocol-agnostic; Pi model selection and completion are injected at runtime.

Purpose: Allow non-Pi agents to reuse `handleSamplingRequest` while Pi keeps its existing model selection and `complete` behavior.
Output: New `interfaces/sampling.ts`, `adapters/pi-sampling-provider.ts`, and refactored `sampling-handler.ts` with no Pi AI/UI imports.
</objective>
