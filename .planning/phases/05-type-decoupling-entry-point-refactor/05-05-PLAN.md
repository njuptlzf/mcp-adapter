<objective>
Introduce the agent-agnostic `createMcpAdapter` entry point in `adapters/entry.ts` and refactor `index.ts` into a thin Pi-specific wrapper. All core registration and lifecycle logic moves into the new entry point; the Pi wrapper only constructs `PiAdapter`, adapts context, loads config/cache, and delegates. Existing Pi consumers see no behavioral change.

Purpose: Complete the universal adapter boundary so future non-Pi agents can call `createMcpAdapter` directly without touching Pi types.
Output: New `adapters/entry.ts`, new `__tests__/entry.test.ts`, updated `index.ts`, and updated `adapters/pi-adapter.ts` if needed.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pi extension host → index.ts | Pi runtime calls `mcpAdapter(pi)`; wrapper must not expose new surfaces |
| index.ts → createMcpAdapter | Config/cache cross from Pi-specific loading into agent-neutral registration |
| createMcpAdapter → AgentAPI | All tool/command/flag registrations and session events cross the agent boundary |
| PiAdapter → Pi runtime | Pi-specific context/renderers are converted at this boundary only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05-01 | Tampering | createMcpAdapter registration timing | mitigate | Keep registration synchronous and immediate, matching current index.ts behavior, so Pi session events are not missed |
| T-05-05-02 | Elevation of privilege | index.ts Pi wrapper | accept | Wrapper has the same privileges as the old index.ts; no new escalation path |
| T-05-05-03 | Repudiation | entry test mock | accept | Test mock is deterministic and records all registration calls for verification |
| T-05-05-04 | Information Disclosure | PiAdapter context conversion | accept | Conversion preserves only the existing fields exposed by AgentContext; no new data leaves the Pi boundary |
| T-05-05-SC | Tampering | npm installs | mitigate | No new packages; if any install is required, apply slopcheck and a blocking human checkpoint for [ASSUMED]/[SUS] packages |
</threat_model>
