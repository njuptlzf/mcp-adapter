**Imports:**
- Type-only imports from `../interfaces/agent-api.ts`: `AgentAPI`, `AgentContext`, `CommandConfig`, `FlagConfig`, `ToolInfo`, `ToolRegistration`, `UISystem`, `FormConfig`, `FormResult`.
- Type-only imports from `../interfaces/sampling.ts`: `SamplingProvider` (used by `adaptQoderContext` to populate `ctx.samplingProvider` — Plan 02 will fill in `QoderSamplingProvider`, but `adaptQoderContext` already accepts the generic `SamplingProvider` so callers can wire any provider).
- Type-only imports from `@qoder-ai/qoder-agent-sdk`: `Query` (used as the type of `queryRef` for `attachQuery` per D-09).
- Runtime import: `{ spawn }` from `node:child_process` (dynamic import inside `exec`, not top-level — keeps tree-shakable).

**`QoderAdapter` class** (implements `AgentAPI`):

- Private/public state:
  - `readonly tools = new Map<string, ToolRegistration>()`
  - `readonly commands = new Map<string, CommandConfig>()`
  - `readonly flags = new Map<string, FlagConfig & { value?: string }>()`
  - `readonly handlers = new Map<string, Set<(...args: unknown[]) => unknown>>()`
  - `private queryRef: Query | undefined`

- Companion methods (NOT part of `AgentAPI`; per Open Question #2 the host calls these after `createMcpAdapter` returns):
  - `attachQuery(q: Query): void` — assigns `this.queryRef = q`. Document with JSDoc that this enables `sendMessage` to push SDKUserMessages into the live session.
  - `detachQuery(): void` — clears `this.queryRef` AND clears any buffered send-message queue (T-06-04: no leak across sessions).

- 8 AgentAPI methods (D-02 full parity):

  1. `registerTool(tool: ToolRegistration): void` — `this.tools.set(tool.name, tool)`. (Qoder consumes tools later via `createSdkMcpServer({ tools: [...adapter.tools.values()] })` — the host builds that bridge.)
  2. `registerCommand(name: string, config: CommandConfig): void` — `this.commands.set(name, config)`. D-08: commands are stored in memory; the host surfaces them via Qoder's `/` slash-command system at session start.
  3. `registerFlag(name: string, config: FlagConfig): void` — `this.flags.set(name, { ...config })` so the `value` field can be mutated later without touching the caller's object.
  4. `on(event: string, handler: (...args: unknown[]) => void | Promise<void>): void` — `this.handlers` map of sets; `add()` (not push, so the same handler registered twice is only called once). Per D-09, the host calls `fireSessionStart(ctx)` etc. to drive simulated events; this method just stores.
  5. `getAllTools(): ToolInfo[]` — return `[...this.tools.values()].map(t => ({ name: t.name }))`. Do NOT include Qoder-native tools — Qoder's session merges `mcp__*` tools into its tool list on its own; the adapter only reflects what's registered through it.
  6. `getFlag(name: string): string | undefined` — `this.flags.get(name)?.value`. If undefined, attempt `process.argv` lookup for `--<name>=<value>` (mirroring Pi's flag resolution). Actually keep it simple: only return registered value. Document the limitation.
  7. `sendMessage(message: unknown, _options?: unknown): void` — if `this.queryRef` has a `streamInput` method (cast through `unknown`), call it. Otherwise no-op + buffer into a small in-memory array (max 32 messages) so tests can assert on it.
  8. `exec(command: string, args: string[]): Promise<unknown>` — dynamic-import `node:child_process`, `spawn(command, args, { stdio: ["ignore", "pipe", "pipe"] })`, collect stdout/stderr, resolve with `{ code, stdout, stderr }`. Reject on `error` event. JSDoc MUST state: "exec is invoked only from trusted host code (e.g. auth-flow, setup), NEVER from MCP tool result content (T-06-04: EoP mitigation)."

- Public event helpers (per D-09 + Pitfall 4 in RESEARCH.md):
  - `async fireSessionStart(runtimeCtx: AgentContext): Promise<void>` — calls `fire("session_start", "session_start", runtimeCtx)`.
  - `async fireSessionShutdown(): Promise<void>` — calls `fire("session_shutdown", "session_shutdown")`.
  - `async fireToolRegistered(name: string): Promise<void>` — calls `fire("tool_registered", "tool_registered", name)`.
  - `private async fire(event: string, ...args: unknown[]): Promise<void>` — `Promise.all([...this.handlers.get(event) ?? []].map(h => Promise.resolve(h(...args))))`. Errors from individual handlers are caught + logged via `console.error` (with the event name + handler count, NOT the args — T-06-02: never log token/message content).

- `readonly ui: UISystem` — minimal per D-07: only `notify`. Implementation: `notify(message, level) => console[level === "error" ? "error" : level === "warning" ? "warn" : "info"](`[mcp-adapter/qoder] ${message}`)`. No `setStatus`, no `form`, no `custom`, no `theme` — explicitly `undefined` (not omitted) so test can assert `adapter.ui.form === undefined`. NEVER include user message content in logs unless the caller explicitly opted in (T-06-02).

**`adaptQoderContext(input)`** — converts a Qoder-like runtime context into a generic `AgentContext`. Signature: `adaptQoderContext(input: { cwd: string; hasUI: boolean; model?: unknown; modelRegistry?: unknown; signal?: AbortSignal; reload?: () => Promise<void>; samplingProvider?: SamplingProvider }): AgentContext`. Returns `{ cwd, hasUI, ui: input.hasUI ? adapter.ui : undefined, model: input.model, modelRegistry: input.modelRegistry, samplingProvider: input.samplingProvider, signal: input.signal, reload: input.reload }`. The Qoder adapter doesn't construct its own `SamplingProvider` here — the host passes one in (or Plan 02's `QoderSamplingProvider` is constructed by the caller and passed via `input.samplingProvider`). This keeps `adaptQoderContext` decoupled from the Qoder SDK's auth surface (T-06-03: no API key here).

**`adaptQoderUI(adapter: QoderAdapter): UISystem`** — convenience export returning `adapter.ui` so callers can grab the UISystem without instantiating twice. (Mirrors `adaptPiUI` pattern, but inlined since `adapter.ui` is already a UISystem.)
