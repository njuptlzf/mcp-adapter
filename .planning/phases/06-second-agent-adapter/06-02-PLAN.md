**`QoderSamplingProvider` class** implementing `SamplingProvider`:

- Constructor:
  ```ts
  constructor(
    private readonly queryFn: typeof query = query,
    private readonly defaultModel?: SamplingModel,
  ) {}
  ```
  Mirrors PiSamplingProvider's constructor injection (see `adapters/pi-sampling-provider.ts` lines 22-26). The optional `defaultModel` lets callers skip `resolveModel` and pass a known model straight into `complete`.

- `async resolveModel(prefs?: ModelPreferences): Promise<SamplingModel | undefined>`:
  - Implementation strategy (per RESEARCH.md Pattern 3):
    1. Try `queryFn({ prompt: "", options: { model: "default" } })` to get a `Query` handle.
    2. Call `handle.getModels()` (control protocol method, verified at `dist/types/options.d.ts:279`).
    3. If `getModels()` returns ≥ 1 model, return `{ provider: first.provider ?? "qoder", id: first.id, name: first.name }`.
    4. If the SDK call fails or returns empty (e.g. qodercli unreachable, see Plan 01's smoke fallback), return `this.defaultModel` if set; otherwise `undefined`.
  - **Never throw** from `resolveModel` — return `undefined` and let the sampling-handler.ts caller fall back. (RESEARCH.md Pitfall 3: throwing here would propagate a confusing SDK error into MCP sampling UX.)
  - Wrap the `query()` + `getModels()` calls in try/catch with `console.debug` logging ONLY that the discovery failed (T-06-03: do NOT log the model id list or any auth token).

- `async complete(model: SamplingModel, request: SamplingRequest): Promise<SamplingResponse>`:
  - Implementation strategy:
    1. Build the `options` object: `{ model: \`${model.provider}/${model.id}\`, maxTokens: request.maxTokens, systemPrompt: request.systemPrompt }`. Pass `signal: request.signal` only if `request.signal` is defined (TypeScript optional handling).
    2. Concatenate `request.messages.map(m => typeof m.content === "string" ? m.content : m.content.map(b => b.text).join(""))` into a single `prompt` string. (Qoder's `query()` takes a single prompt per the SDK's documented shape.)
    3. Call `this.queryFn({ prompt, options })` to get a `Query` handle.
    4. Iterate the async iterable. On `msg.type === "result"`:
       - If `msg.subtype === "success"`, return `{ text: msg.result, model: \`${model.provider}/${model.id}\`, stopReason: "endTurn" }`.
       - If `msg.subtype === "error_max_turns"` or `"error_max_budget_usd"` or `"error_max_structured_output_retries"`, return `{ text: msg.result ?? "", model: ..., stopReason: msg.subtype }`.
       - If `msg.subtype === "error"`, throw `new Error(msg.error ?? "Qoder sampling failed")`.
    5. After the loop, throw `new Error("Qoder sampling returned no result message")`.
  - **T-06-03 mitigation**: do NOT log `request.systemPrompt`, `request.messages`, or the model API key. Only log "Qoder sampling failed for {provider}/{id}" on error. Do NOT catch the throw from step 5 — let it propagate so `sampling-handler.ts` can produce the right MCP error response.
  - Honor `request.signal` for cancellation: pass it into `options.signal` and let the SDK abort the underlying query.

- Optional `confirm(title: string, message: string): Promise<boolean>`:
  - Default implementation: return `true` (auto-confirm). Qoder doesn't expose a programmatic confirm UI at the time of writing, so the Qoder adapter defaults to auto-approve. Document this limitation in JSDoc. Callers that need stricter behavior can pass a custom `confirm` via the constructor (future enhancement; out of scope for Phase 6).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP server → QoderSamplingProvider.complete | Sampling request from MCP server crosses into Qoder LLM call; messages carry user content |
| QoderSamplingProvider → qodercli subprocess | The provider spawns a SDK query that runs qodercli with auth tokens in env |
| QoderSamplingProvider → console.* | Error logging on failure; risk of leaking token / message content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Information Disclosure | `QoderSamplingProvider.complete` | mitigate | Never log `request.messages`, `request.systemPrompt`, or any field that may carry credentials. The test `never logs API keys or message content` enforces this with a regex spy on `console.*`. Error path uses `console.debug` with only the `provider/id` string, no payload. |
| T-06-03b | Information Disclosure | `QoderSamplingProvider.resolveModel` | mitigate | Catches SDK errors silently and returns `undefined`; only logs at `console.debug` level with event name (no model list, no token). |
| T-06-03c | Repudiation | queryFn mock injection | accept | The mock factory in tests is deterministic — every test records the captured arguments, so failures are reproducible. |
| T-06-03d | Elevation of Privilege | signal passthrough | mitigate | `request.signal` is forwarded into `options.signal` so the caller can abort. No fallback `setTimeout` or other way to override caller intent. |
| T-06-03-SC | Tampering | npm installs | mitigate | No new installs in this plan — the SDK was already gated in Plan 01. If a future bump is needed, re-run the SUS checkpoint. |
</threat_model>
