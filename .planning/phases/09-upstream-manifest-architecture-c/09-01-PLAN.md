    Step 1 — `runGit(args, envOverride?)`: wraps `execFileSync("git", args, { encoding: "utf-8", env: { ...process.env, ...envOverride } })`. Returns stdout. On non-zero exit, throws with stderr included.

    Step 2 — `fetchUpstream()`: try `runGit(["fetch", "upstream"])` first; on error, retry with `runGit(["-c", "http.sslVerify=false", "fetch", "upstream"], { GIT_SSL_NO_VERIFY: "1" })`. If both fail, print error + exit 2. Citation: 08-LEARNINGS.md L-4.

    Step 3 — `parseDiff(stdout)`: split by newlines, for each line split on `\t` (git diff --name-status format is `STATUS\tPATH`), filter empty lines, return array of `{ status: string, path: string }`. Trims trailing whitespace from path.

    Step 4 — `parseRegistry(registryPath)`: readFileSync(registryPath, "utf-8"). Match all lines matching `^\\| \`([^\`]+)\` \\|` (backtick-wrapped path in first column). Return `Set<string>` of paths. If the Set is empty after parsing, print error + exit 2 (registry malformed or missing).

    Step 5 — `classify(diffPaths, registryPaths)`: build 3 buckets:
    - `registered` = paths in BOTH diffPaths AND registryPaths (sorted)
    - `divergedButNotRegistered` = paths in diffPaths but NOT in registryPaths (sorted; treated as warning per D-34)
    - `stale` = paths in registryPaths but NOT in diffPaths (sorted; exit 1 trigger)

    Step 6 — `printOutput(buckets, useColor)`: emits the exact 4-section format from D-34 Output block (header line `[divergence-check] upstream ref: main, scanned N files`; GREEN `\u001b[32m✓ registered (X):\u001b[0m` with one indented path per line; YELLOW `\u001b[33m⚠ diverged-but-not-registered (Y): [category: assess]\u001b[0m` with one indented path per line; RED `\u001b[31m✗ stale (registry entry no longer diverged) (Z):\u001b[0m` with one indented path per line; footer `[divergence-check] summary: ...` and `[divergence-check] exit: <code>`). When `useColor === false`, omit the `\u001b[..m` escape sequences entirely (grep-friendly output).

    Step 7 — `main()`: orchestrate fetchUpstream → runGit(DIFF_ARGS) → parseDiff → parseRegistry → classify → printOutput → `process.exit(stale.length > 0 ? 1 : 0)`. Catch any thrown error: print `[divergence-check] FATAL: <message>` + exit 2.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External → Local | Network boundary: `git fetch upstream` pulls untrusted refs from `https://github.com/nicobailon/pi-mcp-adapter` into local working tree. The fetch result is then re-interpreted by the divergence script as path strings. |
| Registry → Script | File-system boundary: `skills/upstream-merge/references/special-cases.md` is a curated input the script parses. A maliciously crafted registry could attempt to influence script behavior, but the script treats registry content as data (Set membership), not as executable instructions. |
| Operator → Script | Invocation boundary: the operator (user / agent) runs `npm run upstream:check` manually. No automated hook. CLI flags (`--no-color`, `--color`) are the only user-controlled inputs. |
| Script → npm | Process boundary: `tsx scripts/upstream-divergence.ts` is spawned by npm; no privileged operations; only reads filesystem + runs `git` subprocess. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | External upstream diff content | mitigate | Script parses `git diff` output as `{status, path}` records split on `\t`; never `eval`s or interpolates path strings into shell commands; only used as Set members for comparison. |
| T-09-02 | Tampering | Registry file (`special-cases.md`) | mitigate | Script extracts paths via a strict regex `^\\| \`([^\`]+)\` \\|`; rejects empty Set (exit 2); does not execute or interpret other registry content (the Decision / Status / Why special columns are display-only). |
| T-09-03 | Repudiation | Script logs | mitigate | Each invocation prints `[divergence-check] upstream ref: main, scanned N files` header and a summary footer with exit code; the script's stdout is the audit trail for the manual merge decision. |
| T-09-04 | Information Disclosure | GnuTLS workaround error path | accept | The workaround uses `GIT_SSL_NO_VERIFY=1` which disables TLS verification. Trade-off accepted: this environment's network cannot use verified TLS for the upstream remote; the workaround is environment-specific (documented in 08-LEARNINGS.md L-4) and applies only to the `git fetch upstream` subprocess — does NOT affect `git fetch origin` (the fork's own remote). |
| T-09-05 | Denial of Service | Large upstream diff | mitigate | Script passes `-- '*.ts' '*.md' '*.json'` to `git diff` (per D-34 input spec), restricting scope to text files; binary files / `node_modules/` / `coverage/` / `dist/` are excluded by the path filter before any Set operations. |
| T-09-06 | Elevation of Privilege | Script execution context | accept | Script runs with the user's normal permissions; no `sudo`, no setuid, no write operations to anything other than process stdout. No file writes, no `git commit`, no `git checkout`. Pure information tool per D-34. |
| T-09-07 | Repudiation (human-side) | Operator may forget to run `npm run upstream:check` before merge | mitigate | SKILL.md §2 step 1 explicitly mandates the script invocation as the FIRST step; SKILL.md §4(e) makes it a merge-completion gate (exit 0 required). Dual-layer mitigation. |
| T-09-SC | Tampering (supply chain) | `tsx` package install | mitigate | `tsx` is already in `devDependencies` (package.json line 115, version `^4.21.0`) — verified by `grep '"tsx"' package.json`. No new install required. The `tsx` package is widely-used (transpiles TS for Node), audited by the npm registry; no `[SLOP]` risk for an already-installed dep. |

## Security Enablement Note

The Phase 9 scope is purely internal refactoring (no external service integration, no auth flow, no new dependency). The trust boundary is between the upstream remote (untrusted) and the local fork (semi-trusted); the script's job is to surface what diverged, not to defend against malicious upstream commits (git's content-addressed integrity handles that at the object level).
