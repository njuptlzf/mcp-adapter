<objective>
Create ProtocolSamplingForwarder and ProtocolElicitationForwarder — the two MCP Server→Client reverse-call forwarders that enable sampling and elicitation for any MCP-compatible agent.

Purpose: These forwarders bridge mcp-adapter's existing SamplingProvider and UISystem.form abstractions to the MCP protocol's Server→Client reverse calls (sampling/createMessage and elicitation/create). They are the core new components of Phase 12's protocol-category simplification (D-06, D-07, D-11).

Output: Two forwarder source files, one Mock MCP Client test fixture, and two unit test files.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Downstream MCP Server → ProtocolSamplingForwarder | Untrusted sampling request crosses from downstream server into mcp-adapter; forwarder must not leak request content |
| Downstream MCP Server → ProtocolElicitationForwarder | Untrusted elicitation request crosses from downstream server; forwarder must not leak response content |
| Forwarder → Agent Client (MCP Server→Client) | Forwarder sends data to Agent Client via server.createMessage/elicitInput; SDK validates via Zod schemas |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Information Disclosure | ProtocolSamplingForwarder.complete() | mitigate | Do not log request.messages or request.systemPrompt — they may contain tokens or user content. Follow T-10-01 pattern: log only event name and error message prefix |
| T-12-02 | Information Disclosure | ProtocolElicitationForwarder.form() | mitigate | Do not log result.content — may contain user PII. Log only result.action ("accept"/"decline"/"cancel") |
| T-12-03 | Tampering | Tool call arguments | accept | Handled by existing CallToolRequestSchema Zod validation in MCP SDK; forwarders pass through SDK-validated types |
| T-12-04 | Spoofing | Client capability declaration | accept | Agent Client declares capabilities during MCP initialization; trust-based per MCP spec. No server-side verification possible |
| T-12-SC | Tampering | npm installs | accept | No new packages installed in this plan — all dependencies existing and verified in RESEARCH.md Package Legitimacy Audit |
</threat_model>
