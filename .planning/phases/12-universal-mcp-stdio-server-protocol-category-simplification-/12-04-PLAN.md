  <action>
    Create __tests__/mcp-server-e2e.test.ts using vitest:

    **Imports:**
    - `Client` from `@modelcontextprotocol/sdk/client/index.js`
    - `StdioClientTransport` from `@modelcontextprotocol/sdk/client/stdio.js`
    - `SpawnOptions` from `node:child_process` (for type annotation)
    - vitest globals: describe, it, expect, beforeEach, afterEach

    **Test structure:**
    - describe("bin/mcp-server.ts E2E", () => { ... })
    - Use a helper function `spawnServer(configPath?: string)` that:
      - Spawns `npx tsx bin/mcp-server.ts` (optionally with --config flag) as a child process via StdioClientTransport
      - Creates a new Client({ name: "test-client", version: "1.0.0" }, { capabilities: { sampling: {}, elicitation: { form: {} } } })
      - Connects the client to the transport
      - Returns { client, transport, process }
    - afterEach: close the client, kill the process

    **Test cases:**
    1. it("lists tools including mcp proxy tool"): spawn server, call client.listTools(), expect tools array to contain a tool named "mcp" with a description and inputSchema
    2. it("executes mcp proxy tool status action"): call client.callTool({ name: "mcp", arguments: {} }), expect response.content to be an array with at least one text content block. The text should contain server status information (may be "MCP not initialized" if no .mcp.json — that's acceptable for this test; the key is that the tool executes and returns content without crashing)
    3. it("server accepts sampling capability declaration"): spawn server with a client that declares sampling capability. Verify the connection succeeds (no error thrown). Call listTools to confirm the server is responsive. (Full sampling forwarding E2E requires a downstream server that requests sampling, which is complex — this test verifies the server starts and accepts the capability declaration without crashing.)

    **Important notes:**
    - Use `vi.setTimeout(15000)` or set timeout on individual tests — subprocess spawn + MCP handshake takes time
    - Use `process.cwd()` as the working directory for the subprocess
    - If no .mcp.json exists in the test directory, the server will log a warning to stderr but should still start and expose the mcp proxy tool
    - Capture stderr output for debugging but don't fail on stderr warnings
    - Use `finally` blocks to ensure subprocess is killed even on test failure

    **Note on D-13 completeness:** The unit tests in Plan 01 (protocol-sampling-forwarder.test.ts, protocol-elicitation-forwarder.test.ts) cover the in-process Mock MCP Client layer. This E2E test covers the subprocess layer. Together they form the dual-layer testing strategy.
