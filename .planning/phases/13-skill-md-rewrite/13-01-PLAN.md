# Phase 13 Plan 01 — SKILL.md Policy Rewrite (MERGE-01, MERGE-02)

## Objective

Rewrite `skills/upstream-merge/SKILL.md` so that the merge policy and follow-up flow reflect the new "upstream-first" principle (per `docs/upstream-merge-retrospective.md` §2.1.2 + §2.1.3).

## Requirements Addressed

- **MERGE-01**: User can run `git merge upstream/main` with default `--theirs` policy in `assess` rows (SKILL.md §4.1)
- **MERGE-02**: SKILL.md §4.2b reduces from 5-step mandatory follow-up to 2-step soft follow-up, with explicit `gh` CLI unavailability fallback

## Source Document

`docs/upstream-merge-retrospective.md` §3.1 P0-1, P0-2

## Tasks

### T1: Rewrite §4.1 assess row to default --theirs

**File:** `skills/upstream-merge/SKILL.md` (~line 99-103 based on prior reads)

**Current text**:
```markdown
| `assess` | Run the §4.1 Pi-coupling marker grep; 0 hits → `--theirs`; ≥1 hit → §4.2b follow-up flow |
```

**New text**:
```markdown
| `assess` | Default `--theirs` (prefer upstream improvements). §4.1 Pi-coupling grep is now **advisory** — 0 hits = clean accept; ≥1 hit = log warning, accept upstream, optionally create §4.2b follow-up issue (best-effort, not blocking). |
```

**Acceptance**: SKILL.md §4.1 row reads "Default `--theirs`" instead of "0 hits → `--theirs`"

### T2: Rewrite §4.2b from 5-step mandatory to 2-step soft

**File:** `skills/upstream-merge/SKILL.md` (~line 160-180)

**Current text** (5-step):
1. Accept the upstream diff first
2. Stage a follow-up commit that refactors the Pi-coupling out
3. Open a follow-up issue
4. Reference the issue number in the merge commit body
5. Do not manually re-edit the upstream diff during merge

**New text** (2-step soft):
```markdown
### 4.2b Pi-coupling soft follow-up (advisory, non-blocking)

When the §4.1 grep returns ≥1 hit in core source, the merge is **not blocked**. Best-effort follow-up:

1. **Accept the upstream diff** (mandatory). `git checkout --theirs <path> && git add <path>`.
2. **Optionally open a follow-up issue** (best-effort, only if `gh` CLI authenticated). Skip if `gh` not authenticated.

> **Removed from v1**: step "Stage a follow-up commit that refactors" is removed. Rationale: fork's decoupling direction has shifted — we accept upstream Pi-coupling as canonical and maintain adapter layer for isolation.
```

**Acceptance**: SKILL.md §4.2b has 2 numbered steps + "Removed from v1" rationale blockquote

### T3: Update §5 (b) Checklist to advisory log

**File:** `skills/upstream-merge/SKILL.md` (§5 Checklist, item b)

**Current**:
```markdown
- (b) Pi-coupling markers = 0 in merged core code
```

**New**:
```markdown
- (b) Pi-coupling markers advisory log (no longer blocking; record hit count in commit body)
```

**Acceptance**: §5(b) text includes "advisory" and "record hit count in commit body"
