# Phase 16 Plan 02 — Execute `git merge upstream/main` with v3.1 protocols

## Objective

Execute the first real `git merge upstream/main` using the v3.1 SKILL.md protocols. **Core principle**: do NOT pre-decide `--theirs` for all files. Instead, follow the correct decision hierarchy:

```
§3.5 (上层: 冲突分类) → §4.4 (中层: 分析协议) → §4.1 (下层: 仅在"需要选一边"时作为默认)
```

## ⚠️ Key Correction from v3.1 retrospective

The v3.1 retrospective established these principles (§2.2 + §3.2.1):
- **同文件不同段落** → 保留两侧（拼接）— NOT `--theirs`
- **同函数冲突** → agent 分析（§4.4 5 步）— NOT auto `--theirs`
- **import 区域** → 检查版本兼容性 — NOT auto `--theirs`
- **§4.1 Default `--theirs`** → 仅在 §4.4 分析后决定"接受 upstream"时才适用

## Requirements Addressed

- Phase 16 success criteria 2-4: "All conflicts resolve via policy/protocol" + "Zero function-level conflicts" + "All commits include merge-mode + pi-coupling-hits metadata"

### T2: Run §3.5 conflict hunk independence check

```bash
# 列出所有 conflict hunk 所在函数
git diff --name-only --diff-filter=U | while read f; do
  awk '
    /^<<<<<<< / { hunk=1; start=NR; next }
    /^=======/ { hunk=0; sep=NR; next }
    /^>>>>>>> / { hunk=0; end=NR; next }
    hunk && match($0, /^(export )?(async )?function ([A-Za-z_][A-Za-z0-9_]*)/, m) { fn=m[2] }
    /^>>>>>>> / { print FILENAME ": hunk@" start "-" end " in function: " fn }
  ' "$f"
done
```

**Output**: For each of the 11 conflict files, classify every hunk into one of 4 categories:

| §3.5 分类 | 含义 | 处理策略 |
|----------|------|---------|
| **同文件 + 不同函数** | ours 和 theirs 改的是不同函数 | ✅ 保留两侧（拼接） |
| **同文件 + 同一函数不同段** | 同一函数内不同行段 | 🟡 §4.4 classify mode |
| **同文件 + 同一函数同一段** | 同一函数同一行段 | 🟡 §4.4 5 步协议 |
| **同文件 + import 区域** | import/require 行冲突 | ✅ 检查版本兼容性 |
